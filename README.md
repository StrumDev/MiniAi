# MiniAi

**MiniAi** is a small chatbot written from scratch in C. It is a real neural network (a recurrent network of the GRU type) trained with backpropagation through time (BPTT). There are no templates and no canned answers: every answer is generated by the network, character by character.

The project has no external dependencies: all you need is a C compiler (`clang` or `gcc`) and the standard C library. It works on Windows, Linux and Android (Termux).

## Quick start

You need `clang` and `make`. In the project root run:

```
make run
```

This command compiles `src/*.c` (flags `-O2 -s`) and immediately starts the program: `MiniAi` on Linux and Android, `MiniAi.exe` on Windows. There are no separate build commands. Multithreading uses `pthread` on Linux and Android and native system threads on Windows.

On Windows, run `make run` from a `sh`-like shell (Git Bash, MSYS2): the start line `./MiniAi.exe` may not work in plain `cmd.exe`. Without `make` you can build the program by hand, for example `gcc -std=gnu11 -O2 -s src/*.c -o MiniAi.exe` (on Linux and Android add `-pthread` and `-lm`).

### Tested platforms

| Platform | Compiler | Result |
|---|---|---|
| Windows | gcc | compiles and works |
| Linux | clang | compiles and works |
| Android (Termux) | clang | compiles and works |

The code uses only the standard C library and a few small system calls, which are split between Windows and POSIX systems (Linux, Android) where needed.

Then, in the MiniAi console:

```
/teach
```

The program trains the model on the files from the `training` folder and saves `model.bin`. After that you can simply type questions. On the next start the model is loaded automatically.

## Commands

Anything that does not start with `/` is treated as a question for the model.

| Command | Action |
|---|---|
| `/teach` | pretraining on all `.pre` files, then fine-tuning on all `.fin` files. If the architecture matches the saved model, training continues from it |
| `/teach pretrain` | the pretraining phase only (plain text) |
| `/teach finetune` | the fine-tuning phase only (pairs from `.fin`) |
| `/teach mixed` | text windows and pairs are shuffled into one set and learned together |
| `/teach new` | train from scratch; can be combined, for example `/teach pretrain new` |


## Training data

All datasets live in the `training` folder. There can be any number of files; the program picks them up by extension:

| Extension | Purpose |
|---|---|
| `.pre` | plain text for **pretraining**: the model learns to predict the next character and picks up the language |
| `.fin` | "question - answer" pairs for **fine-tuning**: the model learns to answer |

Files are processed in alphabetical order. Other files in the folder (for example `notes.txt`) are ignored, and so are hidden files. File names can be anything: `pretrain.pre`, `history.pre`, `greetings.fin`, `facts.fin`.

Pretraining windows never cross from one `.pre` file into the next. A long text is cut into windows of `MaxLength` bytes with a step of `WindowStride`.

The language of the data is up to you: any UTF-8 text works. The sample dataset shipped in `training` is in Ukrainian.

## The `.fin` format

Every pair is two lines:

```
in: "Hi"
out: "Hi! Nice to see you."

in: "What is two plus two?"
out: "Four."
```

Rules:

- Spaces between `:` and the opening quote are ignored.
- The closing quote must be the last character of the line. Spaces and tabs after it are allowed, because they are invisible.
- Quotes inside the text are ordinary characters: `in: "He said "hi" to me"` is a valid entry, and the model will learn those quotes too.
- Any other characters after the closing quote are an error.
- Blank lines and lines starting with `#` (comments) are ignored.
- CRLF line endings and a BOM are supported.

Invalid entries are skipped and the rest of the file is still read. An error is printed as `file:line: description`, for example:

```
./training/extra.fin:4: the closing quote is missing ...
```

The following are also errors: `in:` without `out:`, `out:` without `in:`, empty text, an unknown line. If an `in:` line is broken, its `out:` line is skipped as well, so the pairs do not shift.

## How training works

Training imitates large language models and goes in two stages.

**1. Pretraining (`.pre`).** The model reads plain text and learns to predict the next character at every position. This is how it learns spelling, words and the structure of the language.

**2. Fine-tuning (`.fin`).** The model sees the sequence `question, separator, answer, end` and learns to produce the answer after the separator. By default (`QuestionWeight: 0`) the error is counted on the answer only.

**Mixed mode** (`/teach mixed`) trains on both kinds of data at the same time, in one shuffled set.

Technical details:

- **Architecture.** A character-level (byte-level, vocabulary of 256) GRU network with several layers: `Embedding`, then `Layers` GRU layers of size `Hidden`, then an output layer of 256 values. Cyrillic takes 2 bytes per letter, and the network learns it as bytes.
- **Optimizer.** Adam with warmup (the first 100 steps), gradient norm clipping (`ClipNorm`) and a learning rate decay after every epoch (`PretrainLearningDecay`, `FinetuneLearningDecay`).
- **Parallelism.** Every batch is split between threads (`Threads`, 0 = all CPU cores). Each thread has its own buffers and the gradients are merged afterwards. The batch size should not be smaller than the number of threads, otherwise some threads stay idle (the program warns about this).
- **Dropout** (`Dropout`) between the GRU layers reduces memorizing on small data.
- **Validation** (`ValidationSplit`): a share of the examples is held out for checking. A question is held out together with all of its augmented copies, so the validation is honest.
- **Early stopping** (`Patience`): if validation does not improve for N epochs, training stops and the best model is kept.
- **Question normalization** (`Normalize`): uppercase letters (Latin and Cyrillic) become lowercase, punctuation is replaced with spaces, a dot inside a number and the symbols `+ - * / =` are kept. Normalization is applied both in training and in chat, so "Hello!" and "hello" are the same thing for the model.
- **Augmentation** (`FinetuneAugment`): for every question, damaged copies are created (a dropped word, a missing letter, swapped letters) so that the model tolerates mistakes in questions.

## How an answer is generated

1. The question is normalized.
2. Its bytes are fed into the network one by one, then the separator is fed. This is how the network "reads" the question and builds up its internal state.
3. Then the network outputs a probability distribution for the next character. A character is picked from it (see `Temperature` and `TopK`), fed back into the network, and the step repeats.
4. Generation ends when the network picks the end character or `MaxAnswer` bytes are reached.

`Temperature: 0` always gives the most likely character (deterministic answers). Higher values add variety, but also mistakes. `TopK` limits the choice to a few best characters.

## Chat history mode

It is off by default. Turn it on in `config.yml`:

```
ChatHistory: 1
ChatHistoryTurns: 3
```

or with the command `/set ChatHistory 1`.

The program then remembers the exchanges and, before each new question, gives the model the last `ChatHistoryTurns` exchanges as context. Up to 3/4 of `MaxLength` bytes is reserved for the context (Cyrillic takes 2 bytes per character, so increase `MaxLength` for long conversations).

So that the model does not get lost with context, when `ChatHistory: 1` is on, every pair gets extra copies during fine-tuning that start with random other pairs. Only the last answer is learned. **After turning it on, run `/teach finetune`.**

Commands: `/history` shows the history and `/history clear` clears it. Changing `ChatHistory` with `/set` also clears the history. `/history` shows questions in their normalized form, because that is how they are passed to the model.

**Important:** pairs in `.fin` are independent of each other, so the model learns not to be confused by extra context, but it does not really learn to "remember" the conversation. A question like "what did I ask earlier?" will not be understood.

## Settings in `config.yml`

Format: `Key: value`, one key per line. Lines starting with `#` are comments. All keys are written in PascalCase; fine-tuning keys have the prefix `Finetune` and pretraining keys have the prefix `Pretrain`. The file is found automatically. | `Embedding` | 32 | character vector size (changes the architecture) |

| `Threads` | 0 | number of threads (0 = all cores) |
| `Seed` | 1234 | random seed (0 = new every run) |

| `PretrainEpochs` | 300 | pretraining epochs |
| `PretrainBatchSize` | 2 | pretraining batch size |
| `PretrainLearningRate` | 0.005 | pretraining learning rate |
| `PretrainLearningDecay` | 1 | learning rate multiplier after every epoch |
| `FinetuneEpochs` | 80 | fine-tuning epochs |
| `FinetuneBatchSize` | 4 | fine-tuning batch size |
| `FinetuneLearningRate` | 0.005 | fine-tuning learning rate |
| `FinetuneLearningDecay` | 0.96 | learning rate multiplier after every epoch |
| `FinetuneAugment` | 3 | damaged copies of every question (0 = off) |
| `ClipNorm` | 1 | gradient norm clipping (0 = off) |
| `WeightDecay` | 0 | weight regularization |
| `QuestionWeight` | 0 | loss weight on question characters (0 = learn answers only) |

| `TopK` | 8 | how many best characters to choose from (0 = all) |

## What is stored in `model.bin`

The file holds only the trained weights and a description of the architecture. Training settings, datasets and the chat history are not stored in it. All numbers are written in the machine's native byte order (little-endian on ordinary x86 and ARM processors).

| Offset | Size | Content |
|---|---|---|
| 0 | 8 bytes | signature `MINIAI01` |
| 8 | 4 bytes (`int`) | number of GRU layers |
| 12 | 4 bytes (`int`) | hidden layer size |
| 16 | 4 bytes (`int`) | character vector size |
| 20 | 4 bytes (`int`) | vocabulary size (always 256) |
| 24 | 8 bytes (`long long`) | number of weights |
| 32 | 4 bytes × number of weights | the weights (`float`) as one continuous array |

The order of weights in the array:

1. The character vector table: `256 × Embedding`.
2. For every GRU layer in turn:
   - `Wx`: `3 × Hidden × (input)`, where the input is `Embedding` for the first layer and `Hidden` for the others;
   - `Uh`: `3 × Hidden × Hidden`;
   - bias `bx`: `3 × Hidden`;
   - bias `bh`: `3 × Hidden`.
3. The output layer: weights `256 × Hidden`, then biases `256`.

For the default settings (2 layers, `Hidden` 128, `Embedding` 32) this is 202,496 weights, so the file takes about 790 KB.

On loading, the program checks the signature, the parameter ranges and that the number of weights matches what is expected for this architecture. If the file is damaged or has another version, it is ignored and the model is considered untrained. Saving goes through a temporary file `model.bin.tmp` followed by a rename, so an interrupted write does not damage the previous model.

If the architecture in `config.yml` differs from `model.bin`, `/teach` starts from scratch and overwrites the file. To keep the old model, save a copy of `model.bin`.

## Finding files and folders

`config.yml`, `model.bin` and the `training` folder are searched automatically in these places (in order): the current folder, one and two folders up, the program folder and its parent folders, and the `data/` subfolder in each of these places. So the program can be started not only from the project root. The program folder is determined by a system call of its own platform, and paths on Windows may contain both `/` and `\`.

If `model.bin` is not found, it is created next to `config.yml`.

## Quality tips

- **Little data** (pretraining up to ~1000 words, fine-tuning up to ~50 pairs): keep `Normalize: 1`, `FinetuneAugment` at 3 or more, and `Dropout` around 0.05. The model memorizes the pairs from `.fin` well, but it cannot invent new facts.
- **Early stopping** on tiny data stops training too early, because held-out facts cannot be learned from the others. Turn on `Patience` and `ValidationSplit` only for larger sets.
- **Honest pretraining validation**: overlapping windows (`WindowStride` smaller than `MaxLength`) make validation too optimistic. For an honest estimate set `WindowStride: 0`.
- **Answers seem too "different"**: lower `Temperature` (to 0) or `TopK`.
- **Answers repeat or loop**: raise `Temperature` or lower `MaxAnswer`.
- **Training is slow**: check that `PretrainBatchSize` and `FinetuneBatchSize` are not smaller than the number of threads.
- **More data** calls for a larger `Hidden` and `Layers`, then `/teach new`.

## Limitations

- This is a small character-level model, not a full large language model. It answers what it has learned, and for unfamiliar questions it may produce text-like but meaningless output.
- There is no automatic conversation memory; see the chat history section.
- Encoding: it works with UTF-8; Cyrillic and Latin are lowercased during normalization, and other alphabets are kept as they are.
- Platforms: tested on Windows (gcc), Linux (clang) and Android through Termux (clang). Other systems and compilers (for example macOS or MSVC) have not been tested.
- Windows console: the program turns on UTF-8 and the escape-code mode (for `/clear`) in it. In old consoles without support for them, Cyrillic input may be displayed incorrectly.
